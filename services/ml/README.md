# ml — анализ звучания

Сервис получает файл (ссылку или путь), разбирает звук на CPU и отвечает JSON-ом, который
ложится в строку `track_analysis`: два вектора (звучание и «смысл» в общем пространстве с
текстом), темп, тональность, энергия, настроение, вокал, стили, а для полного файла — сетка
долей, вступление, концовка, участки с голосом и кривая энергии по секундам. Отдельно —
вектор текстового запроса для поиска «спокойный инструментал для работы».

Python 3.13, uv, onnxruntime (только CPU), ffmpeg, FastAPI на `:8403`. В базу не ходит.
Essentia не используется: её колёс нет для linux aarch64, поэтому входы моделей
переписаны на numpy и сверены с настоящей Essentia и с эталонными пакетами на PyTorch.

## Что считается

```
файл ──► ffmpeg (WAV float) ──► моно = среднее каналов ──► soxr HQ: 16 / 22,05 / 48 кГц
            16 кГц ─► мел MusiCNN ─► Discogs-EffNet ─► sound, styles, головы: moods, danceability, voice…
            48 кГц ─► лог-мел CLAP ─► CLAP audio ─► semantic
          22,05 кГц ─► лог-мел ─► Beat This! ─► доли, сильные доли ─► bpm
          22,05 кГц ─► S-KEY ─► тональность ─► Камелот
          |STFT| и лог-мел ─► громкость (K-фильтр) и спектральный поток ─► energyCurve, energy
```

| Поле | Как получается |
|---|---|
| `sound` | Discogs-EffNet: эмбеддинги патчей (128 кадров ≈ 2 с, шаг ≈ 1 с) усредняются и нормируются по L2. 1280 чисел |
| `styles` | 400 стилей Discogs из того же EffNet (выход `activations`), среднее по патчам, первые 10 |
| `moods`, `danceability`, `voice` | головы MTG поверх эмбеддингов патчей, среднее по патчам: вероятность «happy», «sad», «aggressive», «relaxed», «party», «danceable», «voice» |
| `valence` | правило: 0.5 + 0.45·(happy − sad) + 0.15·(party − aggressive). Своих голов валентности для EffNet у MTG нет |
| `semantic` | CLAP: окна по 10 с (превью — три окна встык, полный трек — до 6 окон равномерно), нормированные эмбеддинги окон усредняются и нормируются. 512 чисел |
| `bpm`, `bpmConfidence` | по сетке Beat This!: 60 / средний межударный интервал среди близких к медиане (±7 %) — точнее шага сети в 20 мс. Уверенность — доля ровных интервалов × устойчивость × покрытие трека × сила активаций. Защита от ошибки «вдвое»: вне 60–200 BPM или при 7+ долях в такте темп складывается, а сетка прореживается или достраивается вместе с ним |
| `keyCamelot`, `key`, `keyConfidence` | S-KEY по всему сигналу (короче 3 с или тишина — `null`). Граф ONNX применяет к выходу второй softmax (уверенность прижимается к 1/24) — он обращается точно, уверенность — вероятность победителя |
| `energyCurve` | по секундам, 0..1000: 0,75 × громкость (K-фильтр BS.1770, −40…−5 LUFS → 0…1) + 0,25 × спектральный поток |
| `energy` | 0,6 × «тело» кривой (среднее верхней половины секунд — тихое вступление не делает трек спокойным) + 0,4 × настроение (aggressive, party, 1 − relaxed) |
| `vocalSegments` | вероятность голоса по патчам, медиана по трём, гистерезис 0,6 / 0,4, паузы до 2,5 с склеиваются, участки короче 2 с отбрасываются |
| `introEndMs`, `outroStartMs` | «тело» — где сглаженная энергия ≥ 85 % от 70-го перцентиля хотя бы 8 с. Вступление кончается в начале тела или раньше, если раньше вступает голос (не дальше 40 % трека); концовка — в конце тела, но фраза, которая кончается в пределах 8 с, не обрывается (не раньше 60 % трека). Обе границы притягиваются к сильной доле |
| `beatsMs`, `downbeatsMs` | сетка Beat This! в миллисекундах от начала файла |
| `language` | всегда `null`: язык вокала не определяется (нужна отдельная модель, например Whisper) |

**Превью** (`mode: "preview"`, 30 с MP3 из Deezer): векторы, стили, настроение, темп (по
первым 20 с), тональность, энергия. Поля со временем — `null`: время внутри превью не
ложится на полный файл. **Полный файл** (`mode: "full"`, Opus в .m4a по подписанной ссылке):
всё. В `extra` — то, чего пока нет в `track_analysis`: `approachability` и `engagement`
(головы MTG: «массовость» и «вовлечённость», пригодятся для «Популярное / Редкое» и фона
для работы), `beatsPerBar`, `tempoFold`, `loudnessLufs` (90-й перцентиль громкости по
секундам), служебные числа.

Векторы в JSON — base64 от float16 little-endian (`sound` — 1280 × 2 байта, `semantic` —
512 × 2): ровно то, что хранит `halfvec`. На Rust: `half::f16::from_le_bytes` по парам байт.

**Модели MTG — только для некоммерческого использования** (CC BY-NC-SA 4.0). Личный
сервис без монетизации — ровно этот случай; если DalyWave когда-нибудь станет коммерческим,
EffNet и головы придётся заменить. Атрибуция: Alonso-Jiménez, Serra, Bogdanov, «Music
Representation Learning Based on Editorial Metadata from Discogs», ISMIR 2022; модели —
Music Technology Group, Universitat Pompeu Fabra.

Все адреса закреплены на ревизиях, sha256 проверяется (`src/dalywave_ml/manifest.py`);
фактические суммы файлов после скачивания и экспорта — в `models/manifest.lock.json` и в
`GET /v1/models`.

### Почему CLAP собирается из исходного чекпойнта

Веса `laion/larger_clap_music` на Hugging Face сконвертированы с ошибкой. На transformers
4.57 и 5.22 любые тексты дают почти один вектор (косинус между «calm relaxing music»,
«aggressive heavy rock guitar music», «house music», «classical piano» — 0,999), а
аудиовектор не похож на исходную модель (косинус ≈ 0). Соседние конвертации
(`larger_clap_music_and_speech`, `clap-htsat-unfused`) таких проблем не имеют. Готовый ONNX
от сообщества (`akashiclibrary-dev/larger_clap_music`) сделан из той же сломанной
конвертации. Поэтому образ берёт исходный чекпойнт LAION (2,35 ГБ, sha256 закреплён),
переименовывает веса в формат `transformers.ClapModel` со строгой проверкой (ни одного
лишнего или пропущенного тензора — именно `strict=False` в конвертере transformers
пропустил ошибку), экспортирует аудио- и текстовую башни в ONNX и сверяет их с PyTorch.
Чекпойнт читается безопасно (`weights_only=True`, разрешены только скаляры numpy).

Веса CLAP хранятся в float16, а считаются в float32: перед каждым весом стоит Cast, и
onnxruntime сворачивает его при загрузке сессии. Файлы вдвое меньше (778 → 393 МБ),
скорость та же, косинус с float32 ≥ 0,9999998.

### Русские запросы

CLAP учился на английских подписях, а токенизатор RoBERTa режет кириллицу на байты. Запрос
переводится словарём (`query.py`): ~50 фраз («без слов», «для работы», «под дождь», «в
зал») и ~200 основ слов настроений, жанров, инструментов, занятий и эпох — основа ловит все
формы слова («спокойн» — «спокойный/ая/ое»). Прилагательные и жанры идут первыми, затем
`music`, затем «for …»: «спокойный инструментал для работы» → `calm instrumental music for
focus and work`. Латиница (lo-fi, phonk, имена) проходит как есть, незнакомые русские слова
отбрасываются и возвращаются в `unknownWords`, чтобы пополнять словарь; если не узнано ни
одного слова, уходит исходный текст (`translated: false`). Модель-переводчик (opus-mt-ru-en,
~300 МБ и десятки миллисекунд) для коротких запросов из ограниченного словаря не нужна, а
словарь предсказуем и покрыт тестами.

## Сверка с эталонами

Скрипты в `scripts/`, эталоны считаются в отдельных окружениях с настоящими библиотеками
(в сервис они не входят). Материал — пять 30-секундных превью из `design/fixtures/audio`.

| Что | Эталон | Результат |
|---|---|---|
| Мел-полосы MusiCNN | Essentia 2.1b6 (`FrameCutter` + `TensorflowInputMusiCNN`), тот же сигнал 16 кГц | кадры и патчи совпадают (1876 кадров, 29 патчей); max \|Δ\| 5,5·10⁻⁴ при значениях до 5 — погрешность float32 БПФ, которую log10(1 + 10⁴·x) усиливает у тихих полос |
| Discogs-EffNet (ONNX + наш фронтенд) | `TensorflowPredictEffnetDiscogs`, граф bs64 (.pb) | косинус эмбеддингов патчей ≥ 0,9999999993, трека ≥ 0,99999999985; активации стилей max \|Δ\| 2,8·10⁻⁵ |
| Головы (ONNX) | `TensorflowPredict2D`, графы .pb | max \|Δ\| 4,8·10⁻⁷ |
| EffNet целиком: ffmpeg + soxr против `MonoLoader` | MonoLoader `resampleQuality=0` (лучший sinc) | косинус трека 0,99993–0,99999 |
| | MonoLoader `resampleQuality=1` (по умолчанию) / `=4` (пример в документации MTG) | 0,988–0,994 / 0,989–0,997 — разница только в пересэмплере 44,1 → 16 кГц: модель чувствительна к полосам у 8 кГц |
| CLAP (ONNX float16 + признаки на numpy + tokenizers) | исходный `laion_clap` 1.1.7 с тем же чекпойнтом | лог-мел max \|Δ\| 0,003 дБ; косинус окон ≥ 0,9999998, треков ≥ 0,9999998, текстов ≥ 0,9999996; токены совпадают с `roberta-base` |
| CLAP: экспорт против PyTorch | `ClapModel` с перенесёнными весами | косинус ≥ 0,99999994 (аудио), 1,0 (текст) |
| Beat This! (ONNX + наш лог-мел, нарезка, пики) | пакет `beat_this` 1.1 (чекпойнт final0, sha256 совпал с закреплённым у musetric), `Postprocessor("minimal")` | 7 из 7 сигналов (5 превью, склейка 150 с — 6 кусков и сдвинутый последний, отрывок 12 с): доли и сильные доли совпали все (F = 1,0, max сдвиг 0,0 с), логиты max \|Δ\| 1,6·10⁻⁴ |
| S-KEY (ONNX) | пакет `skey` (Deezer), выход ChromaNet | тональность совпала 7 из 7; вероятности после снятия второго softmax max \|Δ\| 2,2·10⁻⁶ |

Поиск по тексту на превью работает осмысленно: «агрессивный тяжёлый рок с гитарами» → трек
Mytch (стили Metalcore, Post-Hardcore), «house music» → Sayfalse (Electronic---House) —
это проверяет `tests/test_models.py`.

## Скорость

Замер — `ml bench` (модели загружены один раз, время от файла до JSON) и `POST /v1/analyze`
по ссылке. Материал: пять превью Deezer (30 с, MP3 128 кбит/с) и синтетический «полный трек»
4 мин в Opus/.m4a (`scripts/make_full_track.py`). Под рукой нет Neoverse-N1, поэтому
замерено на Mac (Apple M4 Pro) в linux/arm64 Docker с `--cpus 6`.

| Где | Превью 30 с | Полный трек 4 мин |
|---|---|---|
| Docker linux/arm64, 6 ядер — `ml bench`, медиана | **0,97–1,01 с** | **5,3 с** |
| То же через HTTP (`POST /v1/analyze` по ссылке) | 0,97–1,03 с | 5,8–6,2 с |
| Mac без Docker, 6 потоков | 0,44–0,58 с | 3,7 с |
| Цель на сервере (6 ядер Neoverse-N1) | ≤ 2 с | ≤ 15 с |

Где уходит время (Docker, мс):

| Этап | Превью | Полный трек |
|---|---|---|
| ffmpeg → WAV | 70–100 | 450 |
| soxr: 16 / 22,05 / 48 кГц | 10 | 40 |
| Discogs-EffNet + 9 голов | 110–160 | 470 |
| CLAP (3 окна / 6 окон) | 320–380 | 560 |
| Beat This! (20 с / 9 кусков по 30 с) | 300–320 | 3640 |
| S-KEY | 20 | 130 |
| признаки | 1–3 | 3 |

Загрузка моделей — 3 с, вектор текстового запроса — ~10 мс. Память процесса — 1,1 ГБ после
загрузки, 1,3 ГБ в работе, пик 2 ГБ на 4-минутном треке (арена onnxruntime выключена: с
ней процесс держал 3,3 ГБ, а анализ был на 5 % медленнее).

Ядро M4 заметно быстрее ядра Neoverse-N1 (шире NEON, выше частота), так что на сервере всё
будет медленнее: полный трек уложится с запасом, превью окажется ближе к границе в 2 с.
Перед нагрузкой стоит прогнать на сервере
`docker run --rm --cpus 6 dalywave-ml:0.1.0 ml bench <файлы> --modes preview,full`.
Если превью не уложится: окно Beat This! для превью (`PREVIEW_BEAT_FRAMES`, сейчас 20 с)
можно сократить до 15 с — BPM пяти превью при этом менялся не больше чем на 0,2. Полный трек
на 70 % — это Beat This!; если понадобится ускорить и его, у авторов есть облегчённый
чекпойнт `small0` (ONNX для него пришлось бы собирать так же, как для CLAP).

## HTTP API

Поля — camelCase, длительности и моменты — в миллисекундах. Ошибка — статус и
`{"error": {"code": "snake_case", "message": "текст по-русски"}}`. Анализ строго один за раз
на процесс: второй запрос получает `409 busy`, воркер повторяет позже. Текстовые запросы
идут под своим замком и анализ не ждут.

| Запрос | Тело | Ответ |
|---|---|---|
| `POST /v1/analyze` | `{"url": "https://…", "mode": "preview" \| "full"}` или `{"path": "…", "mode": …}` | строка `track_analysis` (см. ниже) + `extra`, `timingsMs` |
| `POST /v1/embed-text` | `{"text": "спокойный инструментал для работы"}` | `{"semantic": "<base64 f16, 512>", "dim": 512, "query": "calm instrumental music for focus and work", "translated": true, "unknownWords": [], "model": "…"}` |
| `POST /v1/taste/train` | набор сети вкуса (ниже) | `{"onnx": "<base64>", "inputDim": 1828, "heads": ["skip", "complete", "like"], "params", "epochs", "reduced", "metrics", "tookMs"}` |
| `GET /v1/healthz` | — | `ok`, загружены ли модели, занят ли сервис, версии python / onnxruntime / ffmpeg, настройки |
| `GET /v1/models` | — | версии моделей (их же пишет `models` в ответе анализа), лицензии, адреса, sha256 файлов, проблемы проверки |

`path` разрешён только внутри `ML_FILES_ROOT` (без неё — `403 path_disabled`). `url`
скачивается целиком во временную папку (до `ML_MAX_DOWNLOAD_MB`) и удаляется после
декодирования. Дольше `ML_MAX_DURATION_S` анализируется только начало (`extra.truncated`).

Ответ `POST /v1/analyze` (`mode: "full"`, сокращён; трек — синтетическая склейка пяти разных
песен, поэтому уверенность темпа и тональности низкая):

```json
{
  "source": "full",
  "models": {"sound": "discogs-effnet-bsdynamic-1", "heads": "discogs-effnet-1",
             "semantic": "larger_clap_music@laion-music_audioset_epoch_15",
             "beats": "beat-this-final0@4e971bd", "key": "skey@9d90d2a",
             "service": "dalywave-ml 0.1.0"},
  "durationMs": 238514,
  "sound": "yBrVHMkgEBay…", "semantic": "zaLbJ+ChxpgA…",
  "bpm": 106.64, "bpmConfidence": 0.194,
  "keyCamelot": "10A", "key": "B minor", "keyConfidence": 0.172,
  "energy": 0.697, "danceability": 0.6967, "valence": 0.603,
  "moods": {"happy": 0.4002, "sad": 0.1743, "aggressive": 0.5269, "relaxed": 0.341, "party": 0.5356},
  "voice": 0.8846, "language": null,
  "styles": [{"name": "Hip Hop---Horrorcore", "p": 0.1381}, {"name": "Rock---Alternative Rock", "p": 0.1117}],
  "introEndMs": 14900, "outroStartMs": 214000,
  "beatsMs": [20, 1380, 2040, 2700], "downbeatsMs": [20, 2040, 6040],
  "vocalSegments": [[15400, 238514]],
  "energyCurve": [278, 280, 305, 301, 258],
  "extra": {"approachability": 0.5444, "engagement": 0.8168, "beatsPerBar": 4.0, "tempoFold": null,
            "loudnessLufs": -9.97, "clapWindows": 6, "patches": 239, "truncated": false,
            "codec": "opus", "sampleRate": 48000},
  "timingsMs": {"fetch": 10, "decode": 517, "resample": 51, "effnet": 535, "clap": 838,
                "beats": 3970, "key": 150, "features": 19, "total": 6093}
}
```

| Код | Когда |
|---|---|
| `invalid_request` 422 | нет ни `url`, ни `path`, или оба; неизвестный `mode`; лишние поля |
| `path_disabled` / `path_forbidden` 403, `not_found` 404 | `path` без `ML_FILES_ROOT`, вне её, нет файла |
| `download_failed` 502, `too_large` 413 | ссылка не скачалась (истекла подпись R2 — 403 от хранилища) или больше лимита |
| `undecodable` 422, `too_short` 422 | ffmpeg не прочитал файл; звука меньше 2 с |
| `busy` 409 | уже идёт анализ |
| `models_missing` 503 | модели не загрузились — причина в `/v1/healthz` |
| `too_little_data` 422, `invalid_dataset` 422 | сеть вкуса: меньше 300 строк (60 на проверку) или у головы один исход; массивы не той длины |

**Сеть вкуса** (`src/dalywave_ml/taste_model.py`) — numpy без torch: строки по времени,
`vectors` (base64 float16, как `halfvec`; уникальные треки × (`soundDim` + `semanticDim`)), `rowVector` (int32:
строка → трек), `scalars` (float32, строки × `scalarDim`), `labels` (float32, строки × 3:
пропуск, дослушивание, лайк), `baseline` (оценка правил), `holdoutFrom` (с этой строки — проверка).
PCA с выбеливанием по трекам обучающей части (звучание → 32, CLAP → 16), MLP 384 → 256 → 64 → 3
(~150 тысяч параметров), Adam, ранняя остановка по последним 15 % обучающей части. Сжатие и
нормировка вшиты в ONNX (opset 17, IR 9): сервер подаёт сырые признаки. Метрики — AUC и logloss по
головам на отложенной части у сети и у правил (их оценка откалибрована логистической регрессией на
обучающей). Обучение под своим замком (второе — `409 busy`), анализ не ждёт. Включать ли сеть,
решает сервер. Крошечная сеть для тестов сервера — `scripts/make_taste_fixture.py`.

## Запуск

```sh
cd services/ml
uv sync
uv run ml models download                       # всё, кроме CLAP, в ./models (sha256, докачка)
uv run --with torch==2.11.0 --with transformers==4.57.6 \
  python export/export_clap.py --out models     # CLAP: скачает чекпойнт 2,35 ГБ и соберёт ONNX
uv run ml models verify
uv run ml analyze ../../design/fixtures/audio/3661025372.mp3 --mode preview
uv run ml embed-text "грустный инди под дождь"
uv run ml serve                                 # HTTP API на :8403
uv run ml bench ../../design/fixtures/audio/*.mp3 --modes preview --repeat 3
```

Проверки:

```sh
uv run ruff check . && uv run ruff format --check . && uv run pytest -q
uv run pytest -m models -q        # на настоящих моделях и превью из design/fixtures/audio
```

`tests/data/musicnn_reference.npz` — эталон мел-полос от настоящей Essentia для
синтетического сигнала (свип, аккорд, шум, тишина), пересоздаётся
`scripts/reference_essentia.py --synthetic`. Сверки целиком — `scripts/validate_*.py`
(порядок запуска — в docstring каждого скрипта); для полного трека без авторских прав
`scripts/make_full_track.py` собирает 4-минутный Opus в .m4a из превью: тихое вступление,
тело, угасающая концовка. Аудио в git не попадает (`bench/out/` в `.gitignore`).

## Docker

```sh
docker build -t dalywave-ml:0.1.0 services/ml
docker run -d --name ml --cpus 6 -p 127.0.0.1:8403:8403 dalywave-ml:0.1.0
```

Модели вшиты в образ при сборке: стадия `clap` ставит torch (CPU-индекс PyTorch), качает
чекпойнт LAION и экспортирует ONNX, всё временное удаляется в том же слое; стадия `models`
качает остальное с проверкой sha256 и докачкой (essentia.upf.edu иногда рвёт соединение).
Стадия `clap` зависит только от `export/`, стадия `models` — от манифеста и загрузчика:
правка анализа модели не перекачивает. ffmpeg собирается из исходников (8.1.3, sha256 и подпись релиза проверены) только
с нужными демультиплексорами и декодерами: MP3, AAC/M4A, Opus и Vorbis в MP4/Ogg/WebM,
FLAC, ALAC, WAV/AIFF — 3 МБ вместо ~420 МБ пакета Debian. Первая сборка на сервере — около
10 минут (в основном скачивание чекпойнта CLAP 2,35 ГБ), дальше — секунды.

Образ — 818 МБ на диске (564 МБ сжатого содержимого): модели 502 МБ (CLAP 393, Beat This!
83, EffNet и головы 23), Python-окружение 198 МБ (onnxruntime 59, numpy 68, tokenizers),
база python:3.13-slim, ffmpeg 3 МБ. Сборка с нуля на этом Mac — 9,5 мин (CLAP 6 мин,
остальные модели 3,5 мин из-за медленного essentia.upf.edu), повторная после правки кода —
10 с.

Сервис в compose: внутренняя сеть, без публикации порта, `ML_URL=http://ml:8403` у Rust.
Память — ~1,3 ГБ на процесс (пик 2 ГБ на 4-минутном треке): веса CLAP разворачиваются в
float32, Beat This! на время куска держит матрицы внимания на 1500 кадров.

## Переменные окружения

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `ML_MODELS_DIR` | `./models` (в образе `/app/models`) | папка моделей |
| `ML_THREADS` | доступные ядра (квота cgroup `--cpus` учитывается) | потоки onnxruntime на модель; модели идут по очереди |
| `ML_FILES_ROOT` | — | папка, внутри которой разрешён `path`; без неё — только `url` |
| `ML_MAX_DURATION_S` | `900` | дольше — анализируется начало |
| `ML_MAX_DOWNLOAD_MB` | `300` | предел размера файла по ссылке |
| `ML_DOWNLOAD_TIMEOUT_S` | `60` | таймаут скачивания |
| `ML_CLAP_WINDOWS` | `6` | окон CLAP по 10 с на полном треке |
| `ML_WORK_DIR` | системная временная | куда скачивать файлы по ссылке |

Процесс обрабатывает один анализ за раз. Нужно больше параллельности — несколько
контейнеров с меньшим `--cpus`/`ML_THREADS` (каждый держит свою копию моделей).

## Ограничения

- `language` не определяется — нужна отдельная модель (Whisper tiny/base определяет язык по
  30 с вокала); «Без слов» уже покрыто `voice`.
- `valence`, `energy`, вступление и концовка — правила поверх моделей, а не обученные модели;
  пороги подобраны на синтетике и превью, их стоит проверить на настоящих полных треках
  (`tests/test_segments.py` фиксирует поведение).
- Головы настроения и голоса обучены на трековых метках; поточечно (по патчам) они дают
  разумную, но не идеальную разметку вокала.
- Скорость измерена на Mac (Apple M4 Pro) в linux/arm64 Docker; ядра Neoverse-N1 медленнее —
  перед нагрузкой стоит прогнать `ml bench` на сервере.
