# Этап 0: YouTube как источник аудио

11.11.2026, Mac arm64, домашний IPv4+IPv6, без cookies. yt-dlp 2026.10.26 (+ejs 0.8.0), Deno 2.7.11/2.9.8 (образ), bgutil 2.0.2, ytmusicapi 1.12.3. Набор `set.json` — 20 треков, по одному, пауза 5 с. Сводки прогонов — `results-*.md`.

## Коротко

- Поиск: 20/20 верно (19 подтверждены отпечатком, «Покажи мне» без превью — сверена по названию, артистам, длительности); верным был первый кандидат.
- Скачивание: Opus itag 251, 124–151 кбит/с, 48 кГц, Ogg без перекодирования; 3,6 МБ на трек.
- YouTube различает адреса: `mweb`+PO-токен на домашнем IPv4 — 403 на всех 20, на IPv6 — работает. Клиенты yt-dlp по умолчанию на IPv4 — 20/20.
- ~10 с на трек, из них 5 с — обязательное ожидание «рекламы» перед потоком.
- Блокировок (bot check, 429, ошибки PO-токена) не было.

## На сервере

См. `compose.bench.yml`: прогоны server-default-pot, server-mweb-pot (`FETCHER_FALLBACK_CLIENTS=none`), server-default (`FETCHER_POT_URL=`). При bot_check — cookies (`FETCHER_COOKIES=/bench/out/cookies.txt`). Есть IPv6 — включить в сети compose и сравнить mweb. Блокировка наглухо — домашний загрузчик.

## Слабые места поиска

Выдача YouTube Music (зависит от страны); альбомы «Various Artists» и совместные релизы; словарь меток только en/ru (+ao vivo/en vivo); два ремикса с похожими подписями и explicit/clean различает только отпечаток или ничто; без превью берётся кандидат с оценкой ≥ 0,9 без проверки; простая транслитерация; набор 20 треков вместо ~200.
