# Спайк: один аудиодвижок на Rust для iOS, iPadOS, macOS и Windows

Проверка риска «звук на iPhone» из этапа 0 (`docs/plan.md`). Движок `dw-audio` (`engine/`) и пробное приложение на Tauri 2.12 (`app/`) с простой страницей на HTML/JS.

## Вердикт: GO — движок на Rust для iOS подходит

Один и тот же код без изменений декодирует все форматы, склеивает треки без пауз до сэмпла и играет в фоне и на заблокированном экране — на macOS и на iOS. Интеграция с системой (аудиосессия, «Сейчас играет», пульт, прерывания, наушники) тоже на Rust, через `objc2`, общая для iOS и macOS. Swift не понадобился.

Что ещё не проверено руками: карточка и кнопки на экране блокировки и в Пункте управления на настоящем iPhone. Симулятор эту карточку не рисует, и автотест экрана блокировки не видит её элементов. Код тот же, что на macOS, где система команды доставила. Проверка — по `DEVICE.md`, 15 минут. Если на телефоне что-то из этого не заработает, запасной путь узкий: перенести на Swift только регистрацию команд, движок остаётся на Rust.

## Цифры

### Декодирование (тест `engine/tests/decode.rs`, по 4 трека на формат)

| Формат | Длина после обрезки | SNR к эталону | Перемотка к произвольному сэмплу |
|---|---|---|---|
| Opus 160k в Ogg | точно | 30–41 дБ | точно; ошибка −64 дБ сразу после точки, через 1 с — 0 |
| Opus 160k в MP4 (`+faststart`) | точно (после своей обработки `elst` и `dOps`) | 30–41 дБ | то же |
| FLAC 16 бит / 44,1 кГц | точно | 90 дБ (предел 16 бит) | бит в бит |
| FLAC 24 бит / 96 кГц | точно | 133 дБ | бит в бит |
| MP3 320 (LAME-заголовок) | точно | 56–60 дБ | бит в бит |
| AAC 256 в M4A | точно (после своей обработки `elst`) | 35–52 дБ | бит в бит |
| Vorbis q6 в Ogg | +4…+43 сэмпла | 40–44 дБ | бит в бит |
| Opus в WebM (дополнительно) | +35…+467 сэмплов | 30–41 дБ | с точностью до миллисекунды |

Лишний хвост у Vorbis даёт экспериментальный кодер Vorbis в ffmpeg: он округляет конечную гранулу вверх до 64 сэмплов. У WebM symphonia не применяет `DiscardPadding`.

### Склейка без пауз (`engine/tests/gapless.rs`, рендер в память в тестовом режиме вывода)

- Выход движка **бит в бит** совпадает с конкатенацией отдельно декодированных треков — все 8 форматов, из файлов и по HTTP с Range. То есть движок не теряет и не вставляет ни сэмпла.
- Непрерывность относительно эталонного свипа: сдвиг на стыках 0,00 сэмпла у FLAC, MP3, AAC, не больше 0,05 у Opus. У FLAC ошибка на стыке равна ошибке в остальном сигнале (−101 дБ у 16 бит, −144 дБ у 24 бит), то есть щелчка нет.
- С ресемплингом (FLAC 44,1 кГц на устройстве 48 кГц): выход **совпадает** с ресемплингом всего альбома одним куском, разница 0. Если ресемплировать каждый трек отдельно, на стыках выходит ошибка с пиком −0,2 dBFS — слышимый щелчок. Цепочка с общим ресемплером его убирает.
- То же на iOS: самопроверка внутри приложения, по HTTP, тем же кодом — результаты совпали с macOS до цифры. Набор длиной 24 с рендерится за 145–400 мс.

### Кроссфейд и громкость (`engine/tests/mixer.rs`)

- Отклонение от равномощной кривой (cos/sin) — 3·10⁻⁸. Наложение начинается ровно за N мс до конца трека, итоговая длина — A + B − N, до сэмпла.
- Нормализация к −14 LUFS по данным от вызывающего (−20 LUFS → +6 дБ) — точно; усиление не поднимает пик выше −1 dBFS.

### Время до звука (от команды до первого сэмпла в колбэке вывода)

### Размер

- iOS, устройство, release, arm64: `.app` — 14 МБ; после strip — 9,5 МБ; в сжатом виде ≈ 4,0 МБ (примерно столько весит загрузка IPA). Это всё приложение: Tauri, обвязка WebView и движок.
- Движок сам по себе (пример-проигрыватель на macOS после strip) — 5,2 МБ: стандартная библиотека, symphonia со всеми кодеками, libopus, rubato, ureq с rustls, cpal.

Проверки шли с громкостью движка 0: вывод CoreAudio работает, но сэмплы нулевые. Позиции, недогрузки и «Сейчас играет» видны в журнале, стыки и кроссфейд проверены рендером в память.

## Как устроен движок

```
источник (HTTP с Range / файл) → symphonia 0.6 + libopus → TrackDecoder (точная обрезка, перемотка)
  → дека: поток декодирования, громкость трека, rubato до частоты устройства
  → кольцевой буфер rtrb (SPSC, без блокировок, 3 с)
  → Mixer в колбэке cpal: N дек (сейчас 4), огибающие, общая громкость
```

- **API**: `Engine::new(config)` → дешёвая потокобезопасная ручка; `load_queue`, `append`, `play`, `pause`, `toggle`, `seek`, `next`, `previous`, `set_volume`, `set_transition(Gapless | Crossfade { ms })`, `stop`. События идут каналом crossbeam: состояние, позиция каждые 250 мс, смена трека (сам или командой), буферизация, ошибка, время до звука, описание кодека. Есть `snapshot()` для синхронных запросов.
- **Колбэк** не выделяет память, не берёт блокировок и не делает системных вызовов. Команды приходят через SPSC-кольцо; освободившиеся деки уходят через другое кольцо и освобождаются в потоке контроллера.
- **«Без пауз»** — цепочка сегментов внутри одной деки: следующий трек открывается заранее, за 30 с до конца, в отдельном потоке. Декодер переключается на него ровно в конце предыдущего, ресемплер не сбрасывается (общий для треков с одной частотой). Смену трека для интерфейса контроллер находит по номеру кадра границы.
- **Кроссфейд** — вторая дека с правилом старта «за N кадров до конца главной»; блок колбэка режется так, что старт попадает в точный кадр. Кривые равномощные; громкость каждого трека применяется в потоке деки.
- **Под «Диджей»** N дек и правила старта уже есть. Добавить: правило «на кадре X другой деки» (сетка долей), эквалайзер и фильтры на деку — в микшере, растяжение времени (Signalsmith Stretch) — в потоке деки, до кольца.
- **HTTP**: ureq + rustls в отдельном потоке. Файл качается целиком в память по Range, декодер читает по мере загрузки. Прыжок далеко вперёд перезапускает загрузку с нужного места, обрыв повторяется с той же позиции. Для Ogg параллельно запрашивается хвост файла (`bytes=-65536`).
- **iOS и macOS** — `engine/src/apple.rs`, около 470 строк на `objc2`.

### Почему objc2 из Rust, а не Swift-плагин Tauri

- MediaPlayer (`MPNowPlayingInfoCenter`, `MPRemoteCommandCenter`) один и тот же на iOS и macOS. На Rust это одна реализация на две системы, а Swift-плагины Tauri бывают только мобильными — для macOS всё равно понадобился бы Rust/objc2.
- Команды пульта идут прямо в движок, без JavaScript и WebView, поэтому работают, даже когда WebView в фоне усыплён.
- Меньше склейки: нет Swift-пакета, регистрации плагина и моста Channel между Swift и Rust. cpal сам сделан на `objc2` и `objc2-avf-audio`.
- Цена: около 470 строк кода с `unsafe`. Пары привязок нет (`MPMediaItemArtwork` для iOS — вызываем селектор через `msg_send!`). Фреймворки надо перечислить в Xcode-проекте (п. 8).

Для Windows то же место займёт SystemMediaTransportControls через крейт `windows` за тем же интерфейсом.

### Контейнер на сервере: Opus в MP4 с `faststart`

- **Старт быстрее**: всё нужное лежит в начале файла. Ogg при открытии читает последние ~64 КБ (symphonia без этого не умеет перематывать) — это +100 мс на медленной сети.
- **«Без пауз» точно**: ffmpeg пишет `elst` и точную длину в `mdhd`, движок обрезает по ним до сэмпла (п. 1–2).
- Ogg тоже работает точно — запасной вариант. WebM брать не надо: в symphonia нет `DiscardPadding`, стыки «плывут» на десятки–сотни сэмплов.
- Для сайта поддержку Opus в MP4 в Safari надо проверить отдельно — это вопрос веб-плеера.

## Проблемы и обходы

1. **symphonia-format-isomp4 0.6.1 не применяет списки правок `elst`.** У AAC остаются 1024 разгонных сэмпла и хвост кадра, у Opus — хвост. Обход: свой минимальный разбор `moov` (`engine/src/mp4.rs`). Начало режется на `elst.media_time`. Длина берётся как `mdhd.duration − media_time`: `elst.segment_duration` у ffmpeg округлён до миллисекунды (для части 1 это −11 сэмплов).
2. **Opus в MP4: `dOps` (big-endian) подаётся адаптеру libopus под видом `OpusHead` (little-endian).** Pre-skip 312 читается как 14337, с первого пакета пропадает 960 сэмплов. Обход: собираем правильный `OpusHead` с нулевым pre-skip и режем сами.
3. **Адаптер libopus применяет pre-skip только к первому пакету после создания декодера** — после перемотки свежим декодером он срезал бы лишнее. Обход: pre-skip обнуляем и для Ogg; обрезка у всех форматов одна — по меткам времени пакетов (`decode.rs`).
4. **Opus после перемотки сходится не бит в бит.** С рекомендованными libopus 80 мс прогрева ошибка −28 дБ, поэтому берём 200 мс: −64 дБ сразу после точки (на перемотке всё равно подъём 5 мс).
5. **Ogg читает хвост файла при открытии.** Обход: параллельный запрос `bytes=-65536` только для Ogg. Для MP4, FLAC и MP3 хвост не нужен и только отнимал бы полосу у начала (FLAC 24/96: 130 → 120 мс).
6. **WebM** — нет `DiscardPadding`, стык неточный. Обхода в движке нет — контейнер не брать.
7. **«Без пауз» с ресемплингом щёлкает, если ресемплировать треки по отдельности** (−0,2 dBFS на стыке). Обход: цепочка сегментов в одной деке с общим ресемплером, длина после ресемплинга — ровно ceil(вход × отношение).
8. **Статическая библиотека Rust не передаёт линковщику Xcode свои `#[link(framework)]`.** Обход: `AVFAudio`, `AudioToolbox`, `MediaPlayer` перечислены в `project.yml`.
9. **Штатная фаза сборки Tauri 2 для Xcode работает только при запущенном `tauri ios dev/build`** («cli-options-server.json … must be running») — просто нажать Run в Xcode нельзя. Обход: своя фаза `app/src-tauri/build-ios.sh` — `cargo build --target …` и копия `libapp.a`; скрипт сам добавляет `~/.cargo/bin` в PATH и фиксирует компилятор для CMake. Схема запускает release.
10. **`cargo tauri ios build` отказывается собирать**: рантайм симулятора 27.0 не совпадает с SDK 27.2. Обход: xcodegen + xcodebuild напрямую.
11. **Отладочная сборка Tauri без `custom-protocol` ищет dev-сервер** — белый экран. Обход: страница статическая, `custom-protocol` включён всегда.
12. **CMake у libopus сбрасывал кэш**, когда путь к компилятору менялся (`/usr/bin/clang` из терминала и clang из набора Xcode), и пытался ставить библиотеку в `/usr/local`. Обход: `CC_<target>`/`CXX_<target>` в `build-ios.sh`.
13. **Синхронные команды Tauri выполняются на главном потоке** — сетевые запросы и ожидание главного потока из него же вешали страницу. Обход: такие команды `async` и `spawn_blocking`.
14. **Прерывание без `shouldResume`:** cpal сам останавливает аудиоюнит, а наш флаг «поток запущен» об этом не знал — быстрое «играть» снимало паузу микшера, но звука не было. Исправлено: всегда зовём `stream.play()`, cpal ведёт своё состояние, повтор безвреден.
15. **Ограничения симуляции**: экран блокировки симулятора не рисует карточку «Сейчас играет», элементы SpringBoard недоступны XCUITest. На macOS `MRMediaRemoteSendCommand` из стороннего процесса система молча игнорирует, синтетические медиаклавиши доходят не всегда. Итог: пульт до движка доходит (на macOS), экран блокировки iOS — на устройстве.
16. **`AVAudioSession.setActive` на главном потоке** — iOS 27 предупреждает о возможной задержке интерфейса (у нас 90–170 мс при старте). Надо активировать в фоне до создания движка.
17. **cpal на macOS** один раз пишет «buffer underrun or overrun» при первом запуске потока; наш счётчик недогрузок — 0, звук не страдает.
18. **Окружение**: `cargo tauri ios init` сам поставил через Homebrew `libimobiledevice` с зависимостями. Диск машины однажды заполнился до нуля (отладочные сборки Tauri под три цели — около 9 ГБ); профили сборки в спайке урезаны.

## Что осталось, чтобы сделать из этого `crates/client/audio`

1. Кэш на диске вместо памяти: разреженный файл с картой диапазонов, общий с загрузками для офлайна, лимит места.
2. Ссылки R2 истекают: при 403 посреди трека — новая ссылка у сервера и продолжение с той же позиции (колбэк «обнови URL»).
3. Смена устройства вывода на macOS и Windows: пересоздать поток, при другой частоте перемотать деки на текущую позицию. На iOS — сброс медиасервисов.
4. Активация аудиосессии не на главном потоке; движок создаётся после неё.
5. Windows: сборка и WASAPI в CI, SystemMediaTransportControls за тем же интерфейсом, что `apple.rs`. Здесь не проверялось — целей Windows нет на машине.
6. «Сейчас играет»: лайк и дизлайк, номер в очереди; на macOS — медиаклавиши и регистрация «играющего» приложения.
7. События прослушивания для сервера поверх событий движка. В фоне не слать позицию в WebView 4 раза в секунду.
8. Режим «Диджей»: старт по кадру другой деки, растяжение времени (Signalsmith Stretch), трёхполосный эквалайзер и фильтры, ограничитель на выходе (сейчас обрезание по ±1).
9. Громкость альбома для склеенных альбомов; правильное сведение многоканального звука в стерео.
10. Меньше потоков и пробуждений: пул подготовки и загрузок, контроллер по событиям вместо тика 20 мс.
11. Отправить исправления в symphonia (`elst`, `dOps` → `OpusHead`, `DiscardPadding`) и убрать обходы.
12. Проверка на iPhone по `DEVICE.md`: экран блокировки, Пункт управления, AirPods, звонок, CPU на FLAC 24/96.

## Как повторить

```sh
cd spikes/ios-audio
python3 tools/gen_audio.py          # тестовое аудио только из ffmpeg: свипы со щелчками на стыках, демо-пьесы, обложки
python3 tools/serve.py --port 8420  # HTTP с Range; --latency-ms 80 --kbps 4000 — «мобильная» сеть
cargo test --release -p dw-audio    # 16 тестов: форматы, перемотка, стыки, ресемплер, кроссфейд, громкость
cd app && DW_VOLUME=0 DW_SCENARIO=background cargo tauri dev   # macOS
```

iOS: `cd app/src-tauri/gen/apple && xcodegen generate`, затем сборка схемы `dw-spike_iOS`. Сценарии: `DW_SCENARIO=background|ttfa|selftest|session|crossfade`, `DW_VOLUME=0`, `DW_SERVER=…`. Журнал лежит в контейнере приложения: `Library/Application Support/rest.daly.wave.spike/dw-spike.log`. UI-тест экрана блокировки — цель `dw-spike_UITests`.
