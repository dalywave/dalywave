# Сховище файлів (чернетка)

Усе, що сервер зберігає сам, — завантажене аудіо, копії для слабкої мережі й для форматів, які браузери
не відтворюють, обкладинки альбомів, виконавців і плейлистів, кліпи, збірки застосунків, файли імпорту, — лежить
в одному сховищі. Варіантів два, їх вибирають через `DALYWAVE_STORAGE`. Власна музика з `DALYWAVE_MUSIC_DIRS`
у сховище не копіюється в жодному з варіантів (див. [music.uk.md](music.uk.md)).

| | `fs` — власна тека | `s3` — S3-сумісне |
|---|---|---|
| Де файли | `DALYWAVE_STORAGE_PATH` (за замовчуванням `/data`) | бакет Cloudflare R2, MinIO, SeaweedFS… |
| Хто віддає клієнтам | сам API: `/api/files/<ключ>?e=…&s=…` | сховище за власним підписаним посиланням |
| Що потрібно | том на диску | бакет і ключ із доступом лише до нього |
| Коли обирати | один сервер, домашня установка | багато файлів, CDN, сервер без великого диска |

## `DALYWAVE_STORAGE=fs`

```env
DALYWAVE_STORAGE=fs
DALYWAVE_STORAGE_PATH=/data
# Лише в docker: адреса API, за якою його бачить сервіс аналізу ml
DALYWAVE_STORAGE_ML_URL=http://api:8400
```

- Тека створюється під час запуску. Вона потрібна **і `api`, і `worker`** — той самий том для читання й запису.
- Плеєр отримує коротке посилання на цей самий сервер (`/api/files/…`), підписане ключем із
  `DALYWAVE_SECRET_KEY`. Входити для нього не потрібно — як і для посилань S3, — але воно діє обмежений час
  (аудіо — 6 годин, завантаження на сервер — 30 хвилин) і підходить лише до свого файлу й методу. Перемотування
  працює (Range, відповідь 206). Зміна `DALYWAVE_SECRET_KEY` скасовує всі видані посилання.
- Адреса в посиланнях — `DALYWAVE_PUBLIC_URL`. Сервіс аналізу `ml` у docker звертається до API через внутрішню мережу,
  тому адресу API для нього задають окремо: `DALYWAVE_STORAGE_ML_URL`.
- Усередині теки — ті самі ключі, що й у бакеті: `audio/…`, `renditions/…`, `images/…`, `imports/…`.
  Файл записується в тимчасовий і перейменовується, тому обірваний запис не лишає половини файлу.
  Порожні теки після видалення прибираються.
- Резервна копія — просто копія теки (`rsync`, `restic`) разом із дампом бази.

## `DALYWAVE_STORAGE=s3`

```env
DALYWAVE_STORAGE=s3
DALYWAVE_S3_ENDPOINT=https://<account_id>.r2.cloudflarestorage.com
DALYWAVE_S3_REGION=auto
DALYWAVE_S3_BUCKET=dalywave
DALYWAVE_S3_ACCESS_KEY_ID=…
DALYWAVE_S3_SECRET_ACCESS_KEY=…
# Якщо клієнти бачать сховище за іншою адресою (SeaweedFS у docker за проксі)
DALYWAVE_S3_PUBLIC_ENDPOINT=
# Якщо сервіс аналізу бачить сховище за третьою адресою
DALYWAVE_S3_ML_ENDPOINT=
```

Якщо `DALYWAVE_STORAGE` порожня, сервер вибирає сам: задано `DALYWAVE_S3_*` — `s3`, задано
`DALYWAVE_STORAGE_PATH` — `fs`, інакше пам’ять процесу (лише для розробки: усе зникає під час
перезапуску, сервер виводить про це попередження).

## Переїзд між варіантами

Ключі однакові, тому переїзд — це копіювання файлів один до одного:

```sh
# s3 → fs: зупинити api і worker, потім
rclone copy r2:dalywave /srv/dalywave/data
# fs → s3
rclone copy /srv/dalywave/data r2:dalywave
```

Після копіювання змініть `DALYWAVE_STORAGE` і запустіть сервер. База не змінюється.
