# Хранилище файлов (набросок)

Всё, что сервер кладёт сам, — скачанное аудио, копии для слабой сети и для форматов, которые браузеры
не играют, обложки альбомов, артистов и плейлистов, клипы, сборки приложений, файлы импорта, — лежит
в одном хранилище. Вариантов два, выбираются `DALYWAVE_STORAGE`. Своя музыка из `DALYWAVE_MUSIC_DIRS`
в хранилище не копируется ни при каком варианте (см. [music.md](music.md)).

| | `fs` — своя папка | `s3` — S3-совместимое |
|---|---|---|
| Где файлы | `DALYWAVE_STORAGE_PATH` (по умолчанию `/data`) | бакет Cloudflare R2, MinIO, SeaweedFS… |
| Кто отдаёт клиентам | сам API: `/api/files/<ключ>?e=…&s=…` | хранилище по своей подписанной ссылке |
| Что нужно | том на диске | бакет и ключ с доступом только к нему |
| Когда брать | один сервер, домашняя установка | много файлов, CDN, сервер без большого диска |

## `DALYWAVE_STORAGE=fs`

```env
DALYWAVE_STORAGE=fs
DALYWAVE_STORAGE_PATH=/data
# Только в docker: адрес API, по которому его видит сервис анализа ml
DALYWAVE_STORAGE_ML_URL=http://api:8400
```

- Папка создаётся при запуске. Она нужна **и `api`, и `worker`** — один и тот же том на чтение и запись.
- Плеер получает короткую ссылку на этот же сервер (`/api/files/…`), подписанную ключом из
  `DALYWAVE_SECRET_KEY`. Вход по ней не нужен — как у ссылок S3, — но она живёт ограниченное время
  (аудио — 6 часов, загрузка — 30 минут) и подходит только к своему файлу и методу. Перемотка
  работает (Range, ответ 206). Смена `DALYWAVE_SECRET_KEY` отменяет все выданные ссылки.
- Адрес в ссылках — `DALYWAVE_PUBLIC_URL`. Сервис анализа `ml` в docker ходит к API по внутренней сети,
  поэтому ему адрес задаётся отдельно: `DALYWAVE_STORAGE_ML_URL`.
- Внутри папки — те же ключи, что в бакете: `audio/…`, `renditions/…`, `images/…`, `imports/…`.
  Файл пишется во временный и переименовывается, поэтому оборванная запись не оставляет полфайла.
  Пустые папки после удаления убираются.
- Резервная копия — просто копия папки (`rsync`, `restic`) вместе с дампом базы.

## `DALYWAVE_STORAGE=s3`

```env
DALYWAVE_STORAGE=s3
DALYWAVE_S3_ENDPOINT=https://<account_id>.r2.cloudflarestorage.com
DALYWAVE_S3_REGION=auto
DALYWAVE_S3_BUCKET=dalywave
DALYWAVE_S3_ACCESS_KEY_ID=…
DALYWAVE_S3_SECRET_ACCESS_KEY=…
# Если клиенты видят хранилище по другому адресу (SeaweedFS в docker за прокси)
DALYWAVE_S3_PUBLIC_ENDPOINT=
# Если сервис анализа видит хранилище по третьему адресу
DALYWAVE_S3_ML_ENDPOINT=
```

Если `DALYWAVE_STORAGE` пуст, сервер выбирает сам: заданы `DALYWAVE_S3_*` — `s3`, задан
`DALYWAVE_STORAGE_PATH` — `fs`, иначе память процесса (только для разработки: всё пропадает при
перезапуске, сервер пишет об этом предупреждение).

## Переезд между вариантами

Ключи одинаковые, поэтому переезд — копирование файлов один к одному:

```sh
# s3 → fs: остановить api и worker, затем
rclone copy r2:dalywave /srv/dalywave/data
# fs → s3
rclone copy /srv/dalywave/data r2:dalywave
```

После копирования поменять `DALYWAVE_STORAGE` и запустить сервер. База не меняется.
